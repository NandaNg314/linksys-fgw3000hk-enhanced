# 03 · 原理与常见问题

> **仅适用于 Linksys FGW3000-HK。**

## 一、解锁权限的原理

### 1.0 开启国内 5G SA 与 ≤5 频段安全收敛准则（重要背景）

FGW3000-HK 的基带是**高通骁龙 SDX55**，硬件完整支持国内四大运营商 5G SA 频段（含港版 UI 默认隐藏的中国移动主力 `n41`、广电/移动 `n28`、电信/联通 `n78` 及 `n79/n1/n3`），但原厂固件默认未开启 SA。

本项目通过修改 CMS 配置开启国内 5G SA，并遵循 **单运营商 ≤ 5 个激活频段（NR + LTE 合计）** 的安全收敛准则：

| NV 键 | 推荐配置示例（中国移动） | 作用与安全说明 |
| --- | --- | --- |
| `threeG_network_mode` | `2` | 选网模式（5G） |
| `threeG_network_sa_mode` | `0` | **SA 开启**（本固件中 `0` = SA 使能，`1` = 降级关闭 SA） |
| `NR_FullBand` / `NR_SupportBand` | `41,28`（电信/联通：`78,1`；广电：`28,41,79`） | 按当前 SIM 卡所属运营商收敛开启 NR 频段 |
| `LTE_FullBand` / `LTE_SupportBand` | `3,41`（电信/联通：`1,3`） | 保留 2 个主力 4G 锚点/回落频段 |
| `APN_Multiple_PDN_Enable` | `0` | **保持单 PDN**，确保 IPQ8074A NSS 硬件加速满速生效 |

> ⚠️ **三条硬件稳定性红线**：
> 1. **总频段数 ≤ 5**：切勿同时勾选 8~10 个 LTE+NR 频段，否则高通 RFLM 射频前端驱动可能触发 `num_shared_xsw <= RFC_MAX_DEVICE` 断言崩溃。
> 2. **保持 `subsys0/restart_level = SYSTEM`**：`startup.sh` 已自动固化，避免基带异常后处于半死循环。
> 3. **避免高频热发 `SIGALRM lte_mgr`**：运行态频繁向 `lte_mgr` 发送 `SIGALRM` 易引发 PCIe MHI/QRTR 队列拥塞（`-12/-16`）；持久化修改频段后建议走一次正常整机冷启动完成附着。

#### 怎么开启 5G SA（具体操作）

**方式一：用 Web 面板（推荐）**

1. 浏览器打开 `http://192.168.15.1/weblog/dashboard.html`，在「蜂窝网络与系统监控」Tab 下拉至频段控制卡片。
2. 点击对应运营商预设（移动 / 电信 / 联通 / 广电），确认 `NR + LTE` 勾选总数不超过 5 个。
3. 选网模式保持 **`5G SA 独立组网`**，点击保存（或使用命令行 `auto_carrier.sh` 一键写入）。

**方式二：命令行（SSH/Telnet）**

```sh
sh /mnt/jffs2/auto_carrier.sh force_cmcc   # 移动 SA（APN=cmnet, NR=41,28, LTE=3,41）
sh /mnt/jffs2/auto_carrier.sh force_ct     # 电信 SA（APN=ctnet, NR=78,1,  LTE=1,3）
sh /mnt/jffs2/auto_carrier.sh force_cu     # 联通 SA（APN=3gnet, NR=78,1,  LTE=1,3）
sh /mnt/jffs2/auto_carrier.sh force_cbn    # 广电 SA（APN=cbnet, NR=28,41,79, LTE=3,41）
sh /mnt/jffs2/auto_carrier.sh once         # 读取 ICCID/PLMN 自动匹配当前运营商
```

**验证是否已跑在 5G SA**：

```sh
# 面板与 API 会直接返回驻留频段、BWP 带宽、MIMO RANK、CQI、5QI 等级与签约速率
curl -s http://127.0.0.1/weblog/api.cgi?action=get_cellular
```

### 1.0.2 基带本地 QRTR 5G IMS 短信收发原理（单 PDN 满速并存）

如果直接在主路由（AP）开启双 PDN（`cid=1` 上网 + `cid=2 ims` 同走 PCIe `rmnet_mhi0`），会破坏高通 NSS/ECM 硬件转发卸载并引发 QMAP 限流。为此，本项目将 5G IMS 客户端下沉至 **SDX55 基带（`10.10.10.3`）本地运行**：

1. **嵌入式承载隔离**：`/data/ims_sip` 通过 Linux `AF_QIPCRTR (42)` 直连基带 QMI WDS，自动建立 `ims` IPv6 Profile 并绑定到基带内部 `rmnet_data0@rmnet_ipa0`，**完全不经过 AP 侧 `rmnet_mhi0`**，主路由保持单 PDN 硬件加速满速。
2. **USIM AKA 硬件鉴权与 SIP 注册**：通过 QMI UIM `0x0034 (QMI_UIM_AUTHENTICATE)` 调用 SIM 卡计算 `AKAv1-MD5` 响应，向运营商 P-CSCF 发起标准 `SIP REGISTER`（携带 `+g.3gpp.smsip`）取得 `200 OK`。
3. **实时收信与上行 `RP-ACK`**：收到 `SIP MESSAGE` 封装的 3GPP `RP-DATA` 后解码 7-bit / UCS-2 及长短信分片，立即回发 `200 OK` 与上行 `RP-ACK` 终结核心网重传，并通过 `55102` HTTP 接口与主路由收件箱、多渠道转发守护无缝同步。

### 1.0.3 5QI/QCI 与 3GPP 5GSM `0xC2` 签约速率（Session-AMBR）零干扰检测原理

- **零干扰静态缓存架构**：同一张 SIM 卡（相同 `IMSI`）在核心网侧的 `5QI/QCI` 等级、`ARP` 与 `Session-AMBR` 属于签约静态属性。基带 `/data/www/cgi-bin/cell_qos` 日常轮询直接读取持久化 `/data/.cached_ambr.json`（**日常 0 次对主路由 PCIe 硬件加速口 `IP_HW0(100)` 的 QMI 端口绑定、0 次后台 `diag_mdlog` 抓包**），彻底避免高频 QMI 绑定干扰 AMSS MHI 环或电源管理状态机；`AT+BNRINFO` 采用 `15s` TTL 与非阻塞 `LOCK_NB` 串口锁。
- **按需 5GSM `0xC2` 签约探测**：当换新卡或手动调用 `?refresh_ambr=1` 时，`/data/probe_ambr.pl` 利用独立临时承载单次捕获 3GPP TS 24.501 §8.3.2.1 标准 **`0xC2 (PDU SESSION ESTABLISHMENT ACCEPT)`** 信令（严格校验 `0x25` DNN 匹配主数据 APN 如 `cmnet`/`cmwap`，排除 `ims`/`sos`），解析必选 6 字节 `Session-AMBR` IE 与 `0x79` QoS Flow 描述后按 `IMSI` 落盘缓存。

### 1.0.4 WAN Raw-IP 双栈自愈与 MHI 静默假死硬件自救

针对运营商夜间基站切频重连及极端基带故障场景：

1. **原生 QMI Raw-IP 路由对齐（免 `udhcpc` 误清地址）**：FGW3000 的 `rmnet_data0` 为高通 QMI Raw-IP 接口，`lte_mgr` 附着后直接通过内核 netlink 下发永久有效 IP（`valid_lft forever`）。`net_orchestrator.sh` 稳态下不驻留 `udhcpc -b`（避免 ping 抖动时 `udhcpc deconfig` 误清空网卡 IP），仅在校验 `PdnList1` 漂移或无地址时按需触发 `mc_trigger wan_ip_renew`。
2. **IPv6 前缀对齐防黑洞**：每分钟非阻塞巡检 `rmnet_data0` 全局 IPv6、默认路由及 `br0` / `radvd.conf` `/64` 前缀一致性，前缀漂移时自动清理失效旧地址并热刷新 `radvd`，消除客户端 Happy Eyeballs 超时卡顿。
3. **SDX55 MHI `M0` 静默假死高置信度硬件自救**：平时由 `block_reboot.sh` 拦截固件误重启；仅当同时满足 **开机满 10 分钟**、**连续 3 分钟 `10.10.10.3` 100% 失联** 且 **内核/QMI 确认 MHI 环满堵死（`qrtr_sendmsg -12` 或 `QCM_DMS_SERVICE_ERR > 15`）** 三个硬条件时，记入 `/mnt/jffs2/wan_events.log` 并自动解除拦截执行整机干净冷启恢复，告别人工拔插电源。
4. **DNS 双保险与内存防爆**：`dnsmasq_wrapper.sh` 严格保留 `strict-order` + `127.0.0.1#6053`（SmartDNS）+ `223.5.5.5` 公共兜底；`proxy_watchdog.sh` 对 `/tmp` 下各类运行日志执行 `300KB` 滚动截断，稳态巡检零 `/mnt/jffs2` 闪存写入。

### 1.0.1 关于 curl 读不到 CA 证书（环境修复）

部分 FGW3000-HK 固件的 `curl` **没有内置默认 CA 根证书路径**，导致直接访问 HTTPS
报 `SSL certificate problem: unable to get local issuer certificate`。
`startup.sh` 里已自动设好环境变量解决（`CURL_CA_BUNDLE` / `SSL_CERT_FILE`）。
若仍遇到，手动执行：

```sh
export CURL_CA_BUNDLE=/etc/ssl/certs/ca-certificates.crt
curl https://www.baidu.com      # 应返回 200
```

> 面板功能不受此影响（api.cgi 里的 HTTPS 拉订阅用了 `-k`）。此修复主要是让
> 命令行 curl / wget 等默认可用。

### 1.1 固件本来就带 Telnet/SSH

FGW3000-HK 原厂固件内置了 Telnet 和 SSH 服务，只是被配置开关关闭 + 防火墙未放行。
解锁 = 把开关打开。

| 文件 | 开关 | 作用 |
| --- | --- | --- |
| `etc/conf/user/sysini.conf` | `sys_telnetd` | 启动 Telnet 服务 |
| `etc/conf/user/sysini.conf` | `sys_gtkshell` | Telnet **免密直入 root** |
| `etc/conf/user/sshd.conf` | `sshd_enable` | 启动 SSH 服务 |
| `etc/conf/user/sshd.conf` | `sshd_port` | SSH 端口（默认 22） |

### 1.2 服务是怎么被拉起来的

- **Telnet**：`bin/cms` 注册了 `TelnetdCallback`。当 `sys_gtkshell=enable` 时，它执行：
  ```
  telnetd -l /mnt/jffs2/bin/login_without_shell_auth > /dev/null 2>&1 &
  ```
  这个脚本内容就是 `exec /bin/sh` → **一连上 Telnet 就是 root，无需密码**
  （`telnetd -l <程序>` 的含义是"连接后直接跑这个程序，而不用 /bin/login 验证"）。
- **SSH**：`bin/msg_center` 检测到 `sshd_enable` 变化后调用 `/bin/sshd_init.sh restart`，
  脚本自动生成主机密钥并启动 `/usr/sbin/sshd -p 22`。密码来自 `etc/shadow`。
- **防火墙**：`bin/firewall.sh` 里端口放行取决于这两个开关：
  ```sh
  if [ "$sys_telnetd" == "enable" ]; then
      iptables -A INPUT -i $sys_wan_if -p tcp --dport 23 -j ACCEPT
  fi
  if [ "$sshd_enable" == "enable" ]; then
      iptables -A INPUT -i $sys_wan_if -p tcp --dport $sshd_port -j ACCEPT
  fi
  ```
  开关一开，端口自动放行。

### 1.3 设备标识与加密

- 配置包 = **AES-128-CBC 加密的 tar.gz**，密钥硬编码在固件 `libgmi.so`：
  `AES_KEY=14381256D62060AE`，`AES_IV=D0466BCC211C849E`。
- 包内含 `passphase`（本机 MAC 标识）、`sysini.conf`、`sshd.conf`、`shadow` 等。
- 恢复时固件会校验标识，**不一致就拒绝**（`Unknow config file` / `Fail to restore config`）。
  → 这就是"必须用自己机器生成的包"的原因。
- 上传/下载走官方接口 `sysconf.cgi`，需带一次性 `confirm_code` + RSA 加密的
  `passphase` + `ui_component`（md5 校验）——所以 F12 脚本必须在已登录的官方页面里跑。

> 注意：固件里有两个名字相近的 `passphase`：
> - 上传参数 `upload_passphase` = 你手输的**备份密码**；
> - 包内 `./passphase` 文件 = 机器的 **MAC 标识**（自动带，不用手输）。

### 1.4 安全性说明

- 不改固件、不刷机、不写 NV 寄存器，只改官方配置里的预留开关。
- 打开的通道仅对**局域网 LAN 侧**有意义，日常使用不受外网暴露影响。
- 若要关闭：把三个开关改回 `disable` 重刷，或恢复出厂设置。
- `enable_telnet.py` 会把 root 密码设为 `admin`，**请仅在受控内网使用，勿暴露公网**。

## 二、常见问题（FAQ）

### 开权限相关

- **Q：`new_config.bin` 能给别人用吗？**
  A：不能。内含原机 MAC，换机校验失败。每台机器都要用它自己的 `Config` 生成。
- **Q：要手动输入自己的 MAC 吗？**
  A：不需要。标识是固件导出备份时自动写进去的，脚本原样保留。
- **Q：脚本报"未找到配置文件"？**
  A：把导出的备份重命名为 `Config`（无扩展名），和脚本放同目录。
- **Q：脚本报解密失败 / cryptography 报错？**
  A：`pip install cryptography`；并确认 `Config` 是本机官方导出的原始包，未改动。
- **Q：控制台报 `pubkey is not defined`？**
  A：不在官方页面 / 未登录。先登录 `http://192.168.15.1`，停在任意官方页面再按 F12。
- **Q：刷入后没重启？**
  A：再执行一遍刷入代码（可安全重复）。

### 5G 相关

- **Q：原厂不是说只支持 NSA 吗？能开 SA 吗？**
  A：基带（SDX55）**硬件支持 SA**，是原厂**固件默认没开**。本项目改 NV 配置开启 SA。
  用 `AT+C5GREG?` 返回 `0,1` 即表示 SA 已注册成功。
- **Q：开了 SA 但网速还是不快？**
  A：速率取决于**信号强度**（RSRP）、**基站负载**、**所在位置覆盖**、**运营商**。
  尽量把 CPE 放在**朝向基站、开阔的窗边**，RSRP 越好速率越高。本项目不承诺固定速率。
- **Q：想要 5G+4G 模式（NSA）怎么办？**
  A：改 `auto_carrier.sh` 里 `apply_carrier_profile` 的 `sa_mode` 取值即可
  （具体取值以你的固件语义为准，改完用 `AT+C5GREG?` 验证）。
- **Q：改了网络模式后掉网/没信号？**
  A：`startup.sh` 有自愈；也可以跑 `sh /mnt/jffs2/auto_carrier.sh once` 重新自适应，
  或重启整机。

### 面板相关

- **Q：测速一直"超时"？**
  A：测速用 **ICMP ping 节点服务器**。有些节点禁 ping 会超时；也可能是节点本身慢。
- **Q：测速数字和手机 App 不一样？**
  A：面板测的是"到节点服务器的 ping"（与手机 App 口径一致）；若改回"经节点访问外网"
  的测法，数字会虚高。当前默认 ping 方式更接近体感。
- **Q：手机还有广告？**
  A：把手机「私人 DNS / 安全 DNS」**设为关闭**。开启时会走 DoT 绕过路由器 DNS。
  路由器已封 853(DoT) 端口，但手机端设置关闭最稳妥。
- **Q：短信功能怎么用？**
  A：原厂 `lte_mgr` 默认将服务域锁为纯数据模式导致 4G/5G 无法收短信。部署本项目 [`docs/02-部署与配置.md`](02-部署与配置.md) 中的基带侧 `modem/ims_sip` 组件后，可在 5G SA 下通过基带本地 QRTR IMS 通道实时接收短信与验证码，并支持微信/邮箱多渠道自动推送。

### 系统相关

- **Q：可写分区满了？**
  A：`/mnt/jffs2` 仅约 13MB。日志放 `/tmp`，别塞大文件。
- **Q：改了 crontab 自启丢了？**
  A：原厂会覆盖 crontab。本项目用 `chattr +i` 加锁；改动前先 `chattr -i`，改完再 `chattr +i`。
- **Q：DNS 断了？**
  A：若没部署 smartdns，`startup.sh` 会自动跳过 DNS 收敛（保持原厂 DNS）。
  若手动改过 `/tmp/dnsmasq.conf`，删掉指向 `127.0.0.1#6053` 的行即可。
