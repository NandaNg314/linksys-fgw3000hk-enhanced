# 03 · 原理与常见问题

> **仅适用于 Linksys FGW3000-HK。**

## 一、解锁权限的原理

### 1.1 固件本来就带 Telnet/SSH

FGW3000-HK 原厂固件内置了 Telnet 和 SSH 服务，只是被配置开关关闭 + 防火墙未放行。
解锁 = 把开关打开。

| 文件 | 开关 | 作用 |
| --- | --- | --- |
| `etc/conf/user/sysini.conf` | `sys_telnetd` | 启动 Telnet 服务 |
| `etc/conf/user/sysini.conf` | `sys_gtkshell` | Telnet **免密直入 root** |
| `etc/conf/user/sshd.conf` | `sshd_enable` | 启动 SSH 服务 |
| `etc/conf/user/sshd.conf` | `sshd_port` | SSH 端口（默认 22） |

### 1.2 服务是怎么被拉起来的

- **Telnet**：`bin/cms` 注册了 `TelnetdCallback`。当 `sys_gtkshell=enable` 时，它执行：
  ```
  telnetd -l /mnt/jffs2/bin/login_without_shell_auth > /dev/null 2>&1 &
  ```
  这个脚本内容就是 `exec /bin/sh` → **一连上 Telnet 就是 root，无需密码**
  （`telnetd -l <程序>` 的含义是"连接后直接跑这个程序，而不用 /bin/login 验证"）。
- **SSH**：`bin/msg_center` 检测到 `sshd_enable` 变化后调用 `/bin/sshd_init.sh restart`，
  脚本自动生成主机密钥并启动 `/usr/sbin/sshd -p 22`。密码来自 `etc/shadow`。
- **防火墙**：`bin/firewall.sh` 里端口放行取决于这两个开关：
  ```sh
  if [ "$sys_telnetd" == "enable" ]; then
      iptables -A INPUT -i $sys_wan_if -p tcp --dport 23 -j ACCEPT
  fi
  if [ "$sshd_enable" == "enable" ]; then
      iptables -A INPUT -i $sys_wan_if -p tcp --dport $sshd_port -j ACCEPT
  fi
  ```
  开关一开，端口自动放行。

### 1.3 设备标识与加密

- 配置包 = **AES-128-CBC 加密的 tar.gz**，密钥硬编码在固件 `libgmi.so`：
  `AES_KEY=14381256D62060AE`，`AES_IV=D0466BCC211C849E`。
- 包内含 `passphase`（本机 MAC 标识）、`sysini.conf`、`sshd.conf`、`shadow` 等。
- 恢复时固件会校验标识，**不一致就拒绝**（`Unknow config file` / `Fail to restore config`）。
  → 这就是"必须用自己机器生成的包"的原因。
- 上传/下载走官方接口 `sysconf.cgi`，需带一次性 `confirm_code` + RSA 加密的
  `passphase` + `ui_component`（md5 校验）——所以 F12 脚本必须在已登录的官方页面里跑。

> 注意：固件里有两个名字相近的 `passphase`：
> - 上传参数 `upload_passphase` = 你手输的**备份密码**；
> - 包内 `./passphase` 文件 = 机器的 **MAC 标识**（自动带，不用手输）。

### 1.4 安全性说明

- 不改固件、不刷机、不写 NV 寄存器，只改官方配置里的预留开关。
- 打开的通道仅对**局域网 LAN 侧**有意义，日常使用不受外网暴露影响。
- 若要关闭：把三个开关改回 `disable` 重刷，或恢复出厂设置。
- `enable_telnet.py` 会把 root 密码设为 `admin`，**请仅在受控内网使用，勿暴露公网**。

## 二、常见问题（FAQ）

### 开权限相关

- **Q：`new_config.bin` 能给别人用吗？**
  A：不能。内含原机 MAC，换机校验失败。每台机器都要用它自己的 `Config` 生成。
- **Q：要手动输入自己的 MAC 吗？**
  A：不需要。标识是固件导出备份时自动写进去的，脚本原样保留。
- **Q：脚本报"未找到配置文件"？**
  A：把导出的备份重命名为 `Config`（无扩展名），和脚本放同目录。
- **Q：脚本报解密失败 / cryptography 报错？**
  A：`pip install cryptography`；并确认 `Config` 是本机官方导出的原始包，未改动。
- **Q：控制台报 `pubkey is not defined`？**
  A：不在官方页面 / 未登录。先登录 `http://192.168.15.1`，停在任意官方页面再按 F12。
- **Q：刷入后没重启？**
  A：再执行一遍刷入代码（可安全重复）。

### 面板相关

- **Q：测速一直"超时"？**
  A：测速用 **ICMP ping 节点服务器**。有些节点禁 ping 会超时；也可能是节点本身慢。
- **Q：测速数字和手机 App 不一样？**
  A：面板测的是"到节点服务器的 ping"（与手机 App 口径一致）；若改回"经节点访问外网"
  的测法，数字会虚高。当前默认 ping 方式更接近体感。
- **Q：手机还有广告？**
  A：把手机「私人 DNS / 安全 DNS」**设为关闭**。开启时会走 DoT 绕过路由器 DNS。
  路由器已封 853(DoT) 端口，但手机端设置关闭最稳妥。
- **Q：短信功能怎么用？**
  A：多数 FGW3000-HK 受基带固件限制（CEMODE 锁定纯数据），**无法收发短信**；
  面板会显示但不可用。

### 系统相关

- **Q：可写分区满了？**
  A：`/mnt/jffs2` 仅约 13MB。日志放 `/tmp`，别塞大文件。
- **Q：改了 crontab 自启丢了？**
  A：原厂会覆盖 crontab。本项目用 `chattr +i` 加锁；改动前先 `chattr -i`，改完再 `chattr +i`。
- **Q：DNS 断了？**
  A：若没部署 smartdns，`startup.sh` 会自动跳过 DNS 收敛（保持原厂 DNS）。
  若手动改过 `/tmp/dnsmasq.conf`，删掉指向 `127.0.0.1#6053` 的行即可。
